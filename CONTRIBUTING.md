# Contributing

This repository uses a lightweight Docs-as-Code workflow.

## Workflow

1. Create an issue describing the documentation or API change.
2. Create a short-lived branch from `main`.
3. Make one focused change.
4. Review the OpenAPI file and related documentation together.
5. Open a pull request and explain what changed and why.
6. Merge only after the completion criteria are met.

## Branch names

- `docs/short-description`
- `openapi/short-description`
- `fix/short-description`

## Commit messages

Write short, specific, imperative messages, for example:

- `Add project requirements`
- `Define review job schema`
- `Clarify validation error response`

## Pull-request checklist

- [ ] The change addresses one clear issue.
- [ ] Examples agree with the OpenAPI schemas.
- [ ] Terminology follows the style guide.
- [ ] Links and Markdown render correctly.
- [ ] The description explains the user benefit.
