# Documentation style guide

## Voice and tone

- Address the reader as **you**.
- Use active voice and present tense.
- Be direct, professional, and supportive.
- Explain the user benefit before implementation details.

## API reference conventions

- Use sentence case for headings.
- Begin operation summaries with an imperative verb, such as **Create** or **Get**.
- Format paths, parameters, properties, and literal values as code.
- Use **ID** rather than **identifier** in user-facing prose.
- Use **review job** consistently; do not alternate with *scan*, *audit*, or *analysis job*.
- Describe requirements with **must** and recommendations with **should**.

## Examples

- Use realistic but fictional content.
- Never include real API keys, personal information, or production URLs.
- Keep examples synchronized with their schemas.
- Explain important response values after showing the example.

## AI-related language

- Call output a **finding** or **recommendation**, not a guaranteed correction.
- State that a technical writer makes the final decision.
- Do not claim that the agent understands, guarantees, or eliminates errors.
